# Porting — Python 문제를 C 로 옮겨 푸는 연습

2주차에 Python 으로 풀었던 basic 문제 중 아홉 개를 C 로 다시 짠다.
알고리즘은 이미 아는 것이므로, 머리를 전부 포인터와 메모리에 쓰기 위한 배치다.

`Data-Structures/` 의 과제는 구조체와 `main` 이 주어지고 함수 하나만 채운다.
여기서는 **빈 파일에서 시작한다.** 그 차이가 이 폴더의 존재 이유다.

## 폴더에 들어 있는 것

| 파일 | 역할 |
|---|---|
| `NN_이름.py` | 2주차에 푼 Python 원본. 왼쪽 창에 띄운다 |
| `NN_이름_output.txt` | 기대 출력. 위 `.py` 를 실행해서 뽑은 뒤 맨 앞에 빈 줄 하나를 더했다 |
| `NN_이름_cases.h` | 입력 데이터만 담긴 헤더. 직접 만들지 않는다 |
| `NN_이름.c` | **오라버니가 만든다.** 이 폴더에 없는 유일한 파일이다 |

`_cases.h` 는 입력만 준다. 배열의 길이는 일부러 빼 두었다.
배열 정의가 눈앞에 보이는 상황에서 길이를 구하는 방법이 C 에 있다.

### 맨 앞의 빈 줄

모든 기대 출력은 **빈 줄 하나로 시작한다.** Python 원본에는 없는 줄이고,
터미널에서 읽기 편하도록 오라버니가 정한 규칙이다 (2026-09-15).

덕분에 모든 섹션 제목을 같은 모양으로 쓸 수 있다.

```c
printf("\n=== 팩토리얼 계산 ===\n");   /* 첫 섹션도 예외가 아니다 */
```

`.py` 를 다시 실행해서 `_output.txt` 를 덮어쓰면 이 빈 줄이 사라진다.
그럴 일이 생기면 맨 앞에 빈 줄을 다시 넣어야 한다.

## 하는 법

```sh
# 1. 빈 파일을 만든다
zed porting/05_recursion.c

# 2. 컴파일만 (문법 확인)
make 05_recursion

# 3. 실행해서 눈으로 본다
make r_05_recursion

# 4. 채점 — 기대 출력과 diff
make d_05_recursion

# 5. 메모리 검사
make v_05_recursion

# 중간에 막히면 gdb
make g_05_recursion
```

`d_` 가 `✅ 출력 일치` 를 찍으면 출력이 글자 단위로 같다는 뜻이다.
`❌` 일 때는 diff 가 함께 나온다. `-` 로 시작하는 줄이 기대값, `+` 가 실제값이다.

## 끝났다고 보는 기준

세 개를 모두 만족해야 한 문제가 끝난다.

1. `make d_...` 가 통과한다
2. `make v_...` 의 `ERROR SUMMARY` 가 `0 errors` 다
3. 시간 복잡도와 **공간 복잡도**를 말로 답할 수 있다. 재귀라면 호출 스택 깊이까지

## 순서

C 가 새로 요구하는 장치가 하나씩만 늘어나도록 배열했다. 알고리즘 난이도 순서가 아니다.

| 순서 | 문제 | 새로 등장하는 것 |
|---|---|---|
| 1 | `05_recursion` | 없음. `int` 하나 들어가고 `int` 하나 나온다 |
| 2 | `11_divide_conquer` | 배열이 처음. 읽기만 한다 |
| 3 | `10_binary_search` | 배열 + 인덱스 산술, `-1` 반환 |
| 4 | `09_number_theory` | 결과가 세 개인 함수. C 는 하나만 반환한다 |
| 5 | `08_bubble_sort` | 배열을 고친다. 호출한 쪽에 변경이 보이는 첫 경험 |
| 6 | `04_brute_force` | 결과 개수를 미리 모른다 |
| 7 | `02_array` | 2차원 배열. 크기가 타입의 일부다 |
| 8 | `01_string` | 문자열. 바꾼 결과를 어느 버퍼에 담을 것인가 |
| 9 | `06_backtracking` | 재귀 + 크기가 변하는 결과 누적 |

## 15분 규칙

알고리즘이 아니라 **뼈대 때문에** 15분을 못 넘기면 로테에게 물어본다.
`#include` 를 무엇을 쓰는지, `main` 의 형태가 무엇인지는 문제가 아니라 문법이다.
바로 알려준다. 막히는 지점이 포인터나 메모리라면 그건 문제이므로 직접 푼다.
